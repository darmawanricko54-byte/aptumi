Security - How We Protect Sensitive Data

Threat Model: Resume contains PII (email, phone, address, NIK). Most checkers upload to S3/server = leak risk + AdSense crawler risk.

Our Architecture:

  • • No /api/upload endpoint exists - grep codebase, you won't find it. File parsing via PDF.js & Mammoth.js in browser memory only.
  • • AdSense only on homepage - /tools/* pages have Content-Security-Policy: connect-src 'self' only, no google ads domain allowed, plus no-store cache. So even if AdSense tried to exfiltrate, browser blocks.
  • • Self-hosted vendors in /js/vendor/ - no CDN call to cdnjs that could be hijacked.
  • • Storage blocking - common.js overrides localStorage.setItem, blocks any key containing resume/email/phone with long value.
  • • Auto wipe - beforeunload + 10min inactivity + manual Wipe button.
  • • Verifiable - Open DevTools > Network > upload file > see 0 POST. Run AptumiSecurity.verify() in console. Check Application > Local Storage = empty.

Audit Steps for You:
1. F12 > Network, 2. Upload resume, 3. Filter Doc/XHR - 0 requests, 4. Application > Storage - empty, 5. View Source - no api/upload
